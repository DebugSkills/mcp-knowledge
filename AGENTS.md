# ➕ Создание скилла (SKILL.md) — чек-лист для AI-агента

1. **Создать** `.knowledge/skills/{slug}/SKILL.md` — slug: `^[a-z][a-z0-9-]*$` (нижний регистр, дефисы).
2. **Frontmatter** — обязательные `name`, `description` (≥20 симв.), `skill_triggers` (≥2) + опциональные (`version`, `token_budget`, `modeSlugs`, `target_roles`, `related_skills`, `related_docs`, `triggers`, `vendor_adaptation`, `compression`, `calibration_status`).
3. **Контент** — QUICK REFERENCE → КОГДА ЗАПУСКАТЬ → ЦИКЛ (таблица) → DECISION TREE → БАЛАНС («что НЕ делать») → ОШИБКИ → СВЯЗАННОЕ + footer `**v1.0** | дата | чейнджлог`. Тонкий: 50-150 строк. Ссылки на файлы вне `.knowledge/` — plain-text, без `.roo/`-путей.
4. **Проверить:** `make -f .knowledge/Makefile validate-canon`
5. **Синхронизировать зеркала:** `make -f .knowledge/Makefile generate-roo-skills generate-cline-skills generate-kilo-skills`
6. **Переиндексировать:** `make -f .knowledge/Makefile index-all` (+ rsync `skills/INDEX.md` в зеркала)
7. **Финальная проверка:** `make -f .knowledge/Makefile check-ssot` + `validate-ecosystem`

## Рабочий пример (обобщённый текст скилла)

Пре-флайт перед глубокой аналитикой / работой с базой знаний MCP-сервером. `<KB_SERVER>` — URL сервера, имена инструментов — референс `mcp-knowledge` (в своей системе замените на свои). Копируйте в `SKILL.md` как есть:

name: kb-mcp-preflight

  Полный цикл проверок перед глубокой аналитической задачей или работой с базой

# 🎯 KB MCP PRE-FLIGHT — полный цикл перед работой с базой знаний

## ⚡ QUICK REFERENCE
| Ситуация | Действие |
|----------|----------|
| Просьба «поработать с базой знаний» / MCP-сервером | Пройти цикл **S1→S6** (read-only), затем обычный workflow |
| Глубокая аналитическая задача (анализ/критика/архитектура) | S1 (health) + S4 (качество) перед загрузкой доменных скиллов |
| Первый поисковый запрос в сессии | Сначала S1-S3: знать здоровье и топологию БД |
| Сервер degraded | Decision Tree ниже → диагностика, НЕ начинать глубокую работу вслепую |
| Индекс в процессе перестройки | Учесть: результаты могут быть неполными; проверить после завершения |

## 🎬 КОГДА ЗАПУСКАТЬ
1. **Пользователь просит работать с базой знаний MCP-сервером** (поиск, анализ, импорт, курирование).
2. **Глубокая аналитическая задача**, которая опирается на знания.
3. **Первый запрос к БД в сессии** — пре-флайт даёт карту данных для точных запросов.
4. **После долгой паузы / рестарта стека** — состояние индекса могло измениться.

## 🔄 ПОЛНЫЙ ЦИКЛ (6 шагов, read-only)
| # | Шаг | Инструмент | Приемлемо | Провал → |
|---|-----|-----------|-----------|----------|
| S1 | **Health** | `GET <KB_SERVER>/health` | `status=healthy`, индекс построен, эмбеддер загружен | Decision Tree / 🚨 Ошибки |
| S2 | **Топология** | list доменов/тем (или knowledge map) | Словарь доменов для точных запросов | Нет домена → искать по-другому |
| S3 | **Зоны/контур** | health → zones + список коллекций | Знать public/private распределение | Контент не в своей зоне → уточнить зону запроса |
| S4 | **Качество** | list открытых issues + очередь устаревшего | Дубли/устаревшее → учитывать при отборе | Массовые дубли → не доверять поиску 1:1 |
| S5 | **Бутстрап контекста** | поиск (топ 5-10) → чтение топ-кандидатов; внутри книг — find_fragment | 3-5 записей = достаточный контекст | Мало → расширить запрос, сменить домен/теги |
| S6 | **Фиксация** | Записать пре-флайт в доску задач (.board.md) | Сводка: health, зоны, топология, отобранные записи | — |

## 🧭 DECISION TREE (после S1)
| Состояние | Действие |
|-----------|----------|
| `healthy`, индекс готов, эмбеддер загружен | Продолжать S2-S6 |
| Индекс `pending`/`reindexing` | Подождать завершения, затем повторный S1 |
| Эмбеддер не загружен | Диагностировать модель/сервис эмбеддингов; поиск не работает без него |
| `status` = `degraded` | Диагностика: liveness, зависимые сервисы (vector DB, embedder), логи; починить или сообщить оператору |
| Сервер недоступен | НЕ начинать глубокую работу; поднять сервер / сообщить оператору |

## ⚖️ БАЛАНС: что НЕ делать
- **Пре-флайт — read-only.** Не запускать тяжёлые операции (скан качества, реиндекс) без явного запроса оператора.
- **Один health на сессию** (кэшировать результат S1). Соблюдать rate limits сервера.
- **Целевой поиск, не веер.** 1-2 точных запроса вместо 10 расплывчатых; читать топ-3-5, а не все результаты.
- **Не тянуть записи в контекст без отбора.** Кандидат с дублем/высокой устарелостью — пометить, читать только при необходимости.
- **Скрытые по умолчанию записи** (deprecated) — включать точечно, не глобально.
- **Не путать источники:** пре-флайт БД ≠ реестр опыта/паттернов проекта. Оба нужны, но это разные источники.

## 🚨 ОШИБКИ
- **401/403** → ключ/уровень не соответствует операции (read для чтения, write для мутаций). Проверить ключ.
- **429 rate limit** → пауза между вызовами; batch-запросы вместо веера.
- **Таймаут** → крупные книги обрабатываются долго; дождаться или отменить операцию.
- **Частичный контент** → проверить счётчики orphans/DLQ в health.
- **Неразрешимая проблема** → зафиксировать и эскалировать оператору, а не «додумывать» данные.
