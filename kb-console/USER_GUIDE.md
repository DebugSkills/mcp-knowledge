# 🖥️ MCP Knowledge Console — руководство пользователя

**kb-console** — веб-интерфейс для проверки и обслуживания MCP Knowledge Server: статус системы, загрузка материалов, поиск по базе знаний. Открывается в браузере на порту **8085**.

## 🚀 Запуск

**На серверном хосте** (вместе с сервером — уже настроено в compose):
```bash
docker compose up -d            # dev
# или из air-gap bundle:
./scripts/offline-deploy.sh deploy
```
→ открыть `http://localhost:8085`

**На клиентском хосте** (отдельно от сервера):
```bash
# CONSOLE_HOST=0.0.0.0 обязателен в bridge-режиме (docker-proxy ходит на IP
# контейнера, 127.0.0.1 внутри через -p недоступен); наружу публикуем loopback.
docker run -d --name kb-console \
  -e MCP_SERVER_URL=http://<server-ip>:8000 \
  -e MCP_API_KEY=<ключ из .env сервера> \
  -e CONSOLE_HOST=0.0.0.0 \
  -e CONSOLE_PASSWORD=<пароль> \
  -p 127.0.0.1:8085:8085 kb-console:prod
# без пароля: -e CONSOLE_AUTH=off  (иначе WARN в логах при каждом старте — bind 0.0.0.0)
```
→ открыть `http://localhost:8085`

## 🔐 Доступ и авторизация

Консоль поддерживает **HTTP Basic auth** (закрывает и веб-страницы, и служебный
websocket-транспорт — обход через WS невозможен; username игнорируется, нужен
только пароль):

| Переменная | Default | Назначение |
|---|---|---|
| `CONSOLE_PASSWORD` | пусто | Пароль Basic auth. Пусто → auth выключен (прежнее поведение). |
| `CONSOLE_AUTH` | `auto` | `auto`: пароль задан → auth включён; пусто + non-loopback bind → предупреждение в логах. `off`: явно выключить. `required`: пустой пароль → контейнер не стартует (прод). |

- **Вход:** браузер покажет стандартное окно логина/пароля → введите любой
  username и пароль из `CONSOLE_PASSWORD`. Креды кешируются на сессию.
- **Logout** — закрыть вкладку/инкогнито-окно; **ротация пароля** — сменить env
  и перезапустить контейнер (как MCP-ключи).
- ⚠️ **Сетевой доступ — только через туннель или TLS:** Basic без TLS передаёт
  пароль base64-кодированным в каждом запросе → `ssh -L 8085:127.0.0.1:8085`
  или TLS-фасад (Caddy/nginx). Прямая публикация порта в сеть без TLS запрещена.
- 📎 **Safari:** не прикладывает сохранённые Basic-креды к websocket-upgrade →
  консоль работает через HTTP-polling (тоже за auth, дыры нет), но отклик чуть
  медленнее. В Chromium/Firefox — полный websocket-транспорт. Это известное
  поведение, не ошибка.

## 📑 Страницы

### 1. Статус
Проверка «всё ли работает»:
- **Карточки компонентов** — сервер, Qdrant, Embedding, Pipeline, DLQ: ✅ зелёное = ок, ❌ красное = проблема (с деталями).
- **Метрики** — очередь, ошибки, размер коллекции, аптайм.
- **Инструменты** — все 20 MCP-инструментов, доступных для вызова.
- Страница обновляется автоматически каждые 10 секунд (кнопка «Обновить» — вручную).

### 2. Импорт
Загрузка материалов в базу знаний — **только через загрузку файла** (.md / .markdown / .txt / .pdf). Ручной ввод текста убран.

**Общий порядок** (все кнопки заблокированы до загрузки файла):
1. Нажмите **«Choose File»** → выберите `.md`, `.txt` или `.pdf`.
2. Кнопки становятся активными в зависимости от типа файла (см. ниже).
3. Заполните/проверьте поля: **тип контента**, **домен**, **предмет** (обязательные), теги (опционально).

**Кнопки (слева направо):**
- **«Преобразовать»** — PDF→текст (только для PDF; для .md/.txt неактивна).
- **«Обработать»** — AI-автоклассификация: domain/subject/tags по содержимому.
- **«Добавить»** — запуск импорта в базу знаний.

**Текстовые файлы (.md / .txt):**
1. Загрузите файл → кнопки «Обработать» и «Добавить» активны.
2. Нажмите «Обработать» → AI предложит domain/subject/tags (можно изменить вручную).
3. Нажмите «Добавить» → импорт.
4. Результат — в **«📊 Отчёт об импорте»** (см. ниже).

**PDF (3 стадии: Преобразовать → Обработать → Добавить):**
1. Загрузите `.pdf` → активна только кнопка «Преобразовать» (текстовый слой или скан — скан обработает OCR).
2. Нажмите «Преобразовать» → PDF→текст, становится активной «Обработать».
3. Нажмите «Обработать» → AI-классификация, становится активной «Добавить».
4. Нажмите «Добавить» → импорт уходит в **«📦 Очередь импорта»** (1 импорт за раз, остальные — в очередь).

**«📦 Очередь импорта»** — карточки операций внутри карточки-отчёта:
- Свёрнутая — статус + прогресс (фаза, N/M секций).
- **Шеврон ▸/▾ раскрывает построчный лог** (parsing/OCR/decompose/indexing/git/done).
- Крестик убирает завершённые (для running — отменяет импорт), «Убрать все» — чистит завершённые разом.

**«📊 Отчёт об импорте»** — большая карточка-обёртка, объединяющая:
- «📦 Очередь импорта» (3 карточки: Преобразовать / Обработать / Импорт).
- После импорта — **ярко-зелёная сводка**: «✅ Импорт выполнен», коллекция, число секций, время обработки.
- При ошибке — красная карточка с описанием ошибки.

**Ограничения PDF:** >100 МБ или >2000 страниц → ошибка с пояснением; зашифрованные PDF не поддерживаются (пароли не хранятся).

### 3. Поиск
Пробная проверка поиска по корпусу:
1. Введите запрос (естественным языком), при необходимости `top_k`.
2. Нажмите **«Найти»** → таблица результатов: заголовок, score, домен, предмет.

## ⚠️ Частые проблемы

| Симптом | Причина / решение |
|---|---|
| Браузер требует логин/пароль | Включён Basic auth (`CONSOLE_PASSWORD`): введите любой username + пароль из env. |
| Консоль не стартует: `CONSOLE_AUTH=required, но CONSOLE_PASSWORD пуст` | Задан режим `required` без пароля — задайте `CONSOLE_PASSWORD` или смените режим на `auto`. |
| «Сервер недоступен» | MCP_SERVER_URL указывает не туда; сервер не запущен (`docker ps`). |
| «Ошибка авторизации» | MCP_API_KEY не задан или не входит в ключи сервера (для импорта нужен ключ с правами записи). |
| Импорт: 0 добавлено | Проверьте domain/subject — обязательные поля; разделы с ошибками перечислены в `failed_sections`. |
| Карточка PDF: «PDF защищён паролем» | Зашифрованный PDF — расшифруйте и загрузите снова; пароли не хранятся на сервере. |
| Лог в карточке пуст | Карточка была завершена давно и удалена из очереди (записи сессионные); лог доступен пока карточка в очереди. |
| Красные карточки в Статусе | Смотрите деталь в карточке; `/health` сервера отдаёт причину (например, Qdrant недоступен). |

## 🔧 Конфигурация (env)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `MCP_SERVER_URL` | `http://localhost:8000` | Адрес MCP-сервера (на клиентском хосте — IP сервера) |
| `MCP_API_KEY` | пусто | Ключ доступа (если на сервере включена авторизация) |
| `CONSOLE_PORT` | `8085` | Порт веб-интерфейса |
| `CONSOLE_HOST` | `127.0.0.1` | Адрес привязки (loopback; `0.0.0.0` — только bridge docker run + `-p 127.0.0.1:8085:8085`) |
| `CONSOLE_PASSWORD` | пусто | Пароль HTTP Basic auth (пусто = auth off) |
| `CONSOLE_AUTH` | `auto` | Режим auth: `auto` / `off` / `required` (см. «Доступ и авторизация») |
| `REFRESH_SECONDS` | `10` | Интервал автообновления страницы «Статус» |
